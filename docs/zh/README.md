## 文档约定

### 写作规则

- **给人读的：一个主题一篇。** 设计、使用与专题文档不按章拆成多个文件；章节编号保持稳定，跨文档引用写「文档名 §章节号」并加链接。
- **给代理读的：拆小、按需读。** `AGENTS.md` 只放路由与全局约束（不超过 80 行）；细则在 `docs/rules/`，一个主题一页，开头写明什么时候读，用英文写。
- **一事一处。** 每个事实只在一处定义，其他地方链接过去。配置项的默认值以 `packages/core/src/config/load-config.ts` 为准，含义以 `pdf2obsidian.config.example.yaml` 注释为准，文档只列常用项。
- **整合，不追加。** 行为变了就改写拥有该主题的那一节，不在文末补一段「更新」。
- **写现状，不写过程。** 文档描述系统现在是什么样；讨论经过与修订历史留在 git 提交里。方案类专题在文首标明状态（方案 / 实施中 / 已实现），实现后改写为现状说明。
- **放置规则：** 架构、模块与接口 → 系统设计；安装、配置、使用与排障 → 使用指南；单一问题的成因、方案与取舍 → `topics/`；术语 → 术语表；给代理的约束 → `docs/rules/`。
- 用词按[术语表](glossary.md)；代码标识符、配置键、命令与接口字段保持原样。

### 中英文同步

- 中文版为准。修改 `docs/zh/` 下任何文档时，在同一提交里同步 `docs/en/` 对应文件；新建文档同时建两种语言，并更新两份索引。
- 两种语言的章节编号与结构一致，便于对照。
- 根目录 `README.md` 面向首次使用者，放简介、快速开始与文档入口；详细配置说明以本目录为准。

### 校验

改文档后核对改动涉及的相对链接与锚点、文件路径、命令和配置键是否与代码一致（见 [verification 规则](../rules/verification.md)）。
